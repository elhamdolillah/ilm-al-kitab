# مهمة: رفع نسبة اللغة الرياضية في مشروع علم الكتاب

## السياق

مشروع "علم الكتاب" (ilm-al-kitab) هو مشروع لبناء اللغة العربية الرياضية (MAL)
مع مترجم AOT يولّد كود x86-64 Assembly. تم مؤخراً كتابة تمثيل رياضي صرفة
لتعليمات Assembly (mov, add, call, jmp, push, pop, cmp, test, loop, syscall)
كجزء من رفع نسبة المحتوى الرياضي في المشروع.

## المهمة المطلوبة

أريد منك إنشاء **وثيقة رياضية رسمية شاملة** تغطي:

### 1. التمثيل الرياضي الكامل لتعليمات x86-64 Assembly

اكتب تعريفات رياضية صرفة لجميع تعليمات Assembly التالية باستخدام:
- نظرية المجموعات (Set Theory)
- المنطق الرمزي (Predicate Logic)
- نظرية الأنواع (Type Theory)
- الدوال والتراكيب (Function Composition)

التعليمات المطلوبة:

**فئة نقل البيانات:**
- MOV, XCHG, LEA, MOVZX, MOVSX, CMOV

**فئة المكدس:**
- PUSH, POP, PUSHF, POPF, ENTER, LEAVE

**فئة العمليات الحسابية:**
- ADD, SUB, INC, DEC, NEG, MUL, IMUL, DIV, IDIV, CMP, ADC, SBB

**فئة العمليات المنطقية:**
- AND, OR, XOR, NOT, TEST, SHL, SHR, SAR, ROL, ROR, RCL, RCR

**فئة التحكم في التدفق:**
- JMP, JE/JZ, JNE/JNZ, JL/JNGE, JGE/JNL, JLE/JNG, JG/JNLE
- JB/JC, JAE/JNC, JBE/JNA, JA/JNBE, JS, JNS, JO, JNO, JP, JNP
- CALL, RET, LOOP, LOOPE, LOOPNE, JCXZ

**فئة السلاسل:**
- MOVSB/W/D/Q, STOSB/W/D/Q, LODSB/W/D/Q, CMPSB/W/D/Q, SCASB/W/D/Q
- REP, REPE, REPNE

**فئة النظام:**
- SYSCALL, INT, IRET, HLT, NOP, CLI, STI, CLD, STD, CQO, CDQ

**فئة الفاصلة العائمة:**
- FLD, FST, FSTP, FADD, FSUB, FMUL, FDIV, FSQRT, FABS, FCHS
- FCMP, FCOM, FCOMI, FILD, FIST, FLDZ, FLD1

**فئة SIMD:**
- MOVDQU, MOVDQA, PADDB/W/D/Q, PSUBB/W/D/Q, PMULLD, PMULUDQ
- PAND, POR, PXOR, PCMPEQD, PCMPGTD, PSHUFD, PUNPCKLDQ, PUNPCKHDQ

### 2. النظام الرياضي الموحد

أنشئ نظاماً رياضياً موحداً يتضمن:

```
فضاء الحالة: Σ = M × R × F × S
حيث:
- M = ℤ₂⁶⁴^(2⁶⁴) — فضاء الذاكرة
- R = {rax, rbx, rcx, rdx, rsi, rdi, rsp, rbp, r8...r15, rip, rflags}
- F = {CF, ZF, SF, OF, PF, AF} — الأعلام
- S = ℤ₂⁶⁴* — المكدس

دوال الوصول:
- rd: R × Σ → ℤ₂⁶⁴ (قراءة مسجل)
- wr: R × ℤ₂⁶⁴ × Σ → Σ (كتابة مسجل)
- rm: ℤ₂⁶⁴ × ℕ × Σ → ℤ₂⁶⁴ (قراءة ذاكرة)
- wm: ℤ₂⁶⁴ × ℤ₂⁶⁴ × ℕ × Σ → Σ (كتابة ذاكرة)

العمليات المعيارية:
- a +₆₄ b = (a + b) mod 2⁶⁴
- a -₆₄ b = (a - b) mod 2⁶⁴
- a ×₆₄ b = (a · b) mod 2⁶⁴
```

### 3. الدلالات التشغيلية (Operational Semantics)

اكتب الدلالات التشغيلية الصغرى (Small-Step Semantics) للبرامج:

```
σ →ᵢ σ'  (تنفيذ تعليمة واحدة)

القواعد:
─────────────────────────
⟨nop; P, σ⟩ → ⟨P, σ⟩

σ →ᵢ σ'
─────────────────────────
⟨I; P, σ⟩ → ⟨P, σ'⟩

σ →꜀ₐₗₗ(ₐ) σ'
─────────────────────────
⟨call(addr); P, σ⟩ → ⟨func(addr); ret; P, σ'⟩
```

### 4. نظرية الأنواع لتعليمات Assembly

أنشئ نظام أنواع بسيط:

```
Types = {Int64, Int32, Int16, Int8, Float64, Float32, Ptr(T), Vec128}

قواعد الكتابة:
- mov: Ptr(T) → T → Unit
- add: Int64 → Int64 → Int64
- push: T → Stack(T)
- pop: Stack(T) → T
```

### 5. أمثلة تطبيقية

اكتب 5 أمثلة تطبيقية توضح كيفية استخدام التمثيل الرياضي:
1. حلقة جمع عناصر مصفوفة
2. دالة حساب مضروب (فاكتوريال)
3. طباعة نص
4. قراءة من الإدخال
5. استدعاء دالة مع وسيطات

### 6. الربط مع MAL

اشرح كيف يمكن استخدام هذا التمثيل الرياضي لـ:
- التحقق من صحة كود Assembly المولّد من مترجم MAL
- إثبات خصائص البرامج المكتوبة بـ MAL
- بناء مترجم صحيح بالتصميم (Correct-by-Construction)

## القيود

- لا تستخدم أي كود تنفيذي (لا Python, لا Rust, لا C)
- جميع التعريفات يجب أن تكون رياضية صرفة
- استخدم الترميز الرياضي القياسي (∀, ∃, ∈, ⊆, ∪, ∩, ×, →, ⇔, ∧, ∨, ¬)
- كل تعريف يجب أن يكون دقيقاً وغير قابل للتأويل
- لا تختلق خصائص غير موجودة في التعليمات الفعلية
