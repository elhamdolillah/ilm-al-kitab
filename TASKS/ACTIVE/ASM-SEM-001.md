# ASM-SEM-001 — عقد الحالة ودلالات التعليمات الأساسية

## الحالة

`PROVEN_FOR_SCOPE`

## الهدف

تحويل مسودة دلالات x86 إلى أول نطاق تنفيذي صغير يمكن اختباره offline وربطه لاحقاً بـMAL دون تعديل Parser أو Compiler الحاليين.

## النطاق

التعليمات المسموح بها في المرحلة الأولى:

```text
mov add sub push pop cmp test
```

والأنواع:

```text
Int64 Register Address Width8
```

## خارج النطاق

```text
SIMD floating point interrupts fork execve epoll pipe2
```

كما أن `syscall` لا يدخل إلا في مهمة لاحقة منفصلة تحدد حدود sandbox.

## العقد

كل تعليمة تحول حالة صالحة إلى حالة صالحة أو تعيد خطأً صريحاً:

```text
Instruction × State ⇀ State + Error
```

ولا يجوز تحويل فشل الذاكرة أو overflow أو register غير معروف إلى نجاح صامت.

## معايير القبول

- تعريف IR صغير مستقل عن تفاصيل AST الحالية.
- اختبارات push/pop تحفظ قيمة المسجل وrsp عند النجاح.
- اختبارات add/sub للحالات العادية وحدود 64-bit.
- اختبارات cmp/test للأعلام التي تتغير فقط.
- اختبارات فشل للعرض والعنوان والمسجل غير الصالح.
- stdout خام وexit code وSHA-256.
- عدم تغيير baseline أو إعلان `PROVEN_FOR_SCOPE` قبل اكتمال كل ذلك.

## الترتيب

1. مراجعة المسودة والدستور.
2. تثبيت types وError contract.
3. تنفيذ model صغير offline.
4. تشغيل corpus.
5. مراجعة diff.
6. توثيق الحالة فقط بعد نجاح الاختبارات.

## قرار السلامة

لا تضاف التعليمات إلى MAL Parser أو AOT compiler في هذه المرحلة. المسار الأول هو نموذج دلالي مستقل؛ هذا يمنع تلويث النواة بميزات لم تثبت بعد.
